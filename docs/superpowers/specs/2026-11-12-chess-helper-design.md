# Шахматный помогатор — дизайн

Дата: 2026-11-12
Статус: реализован; обновлён 2026-11-12 по итогам ревью кода

## Цель

Десктоп-окно с шахматной доской, в котором пользователь вручную повторяет ходы
партии, идущей в другом месте (Discord, Chess in the Park): и свои, и соперника.
Когда ход за пользователем, окно показывает три лучших хода от Stockfish —
стрелками на доске и списком с оценкой.

## Не входит в эту версию

- Чтение экрана / автоматическое распознавание позиции из Discord.
- Сохранение партий, экспорт PGN, история между запусками.
- Часы, контроль времени.
- Выбор фигуры при превращении (всегда ферзь, см. ниже).
- Подсказки на ходу соперника.

## Стек

| Часть | Технология |
|---|---|
| Окно | `pywebview` (Windows → Edge WebView2), встроенный HTTP-сервер pywebview (`http_server=True`) |
| Бэк | Python 3.13, `python-chess` (правила + UCI-клиент) |
| Движок | Stockfish 17.x, сборка Windows x64 (avx2), файл `engine/stockfish.exe` |
| Фронт | чистый JS (ES-модули, без сборщика), доска `chessground` |
| Тесты | `pytest` |
| Зависимости | uv: pyproject.toml + uv.lock, версия Python в .python-version |

Python 3.13, а не 3.14: pywebview на Windows зависит от `pythonnet`, у которого
поддержка 3.14 не гарантирована.

Путь к движку можно переопределить переменной окружения `STOCKFISH_PATH`.

`chessground` ставится через npm один раз, после чего нужные файлы копируются в
`frontend/vendor/chessground/` (`dist/*.js` и `assets/*.css`). Во время работы
приложения `node_modules` не нужен; модуль подключается через import map в
`index.html`.

## Структура файлов

```
app.py                     # запуск: окно + связка фронта с бэком, логирование
backend/
  __init__.py
  game.py                  # GameSession: состояние партии
  engine.py                # EngineAnalyzer: Stockfish в фоне, MultiPV 3, поток-курьер доставки
  api.py                   # Api: методы, которые вызывает JS; номер версии позиции
frontend/
  index.html               # разметка + import map
  main.js                  # доска, панель, обработка событий
  style.css
  vendor/chessground/      # скопированные файлы chessground
engine/
  .gitkeep                 # папка есть в git; stockfish.exe кладётся вручную и игнорируется
tests/
  test_game.py
  test_engine.py           # с настоящим Stockfish
  test_engine_unit.py      # без Stockfish: процесс движка подменён фейком
  test_api.py
pyproject.toml             # зависимости (uv)
uv.lock
.python-version            # 3.13
README.md                  # как поставить и запустить (английский и русский)
LICENSE                    # GPL-3.0
.gitignore                 # .venv/, node_modules/, engine/* кроме .gitkeep, __pycache__/
```

Файлы `frontend/vendor/chessground/` коммитятся в репозиторий, чтобы для запуска
не нужен был npm. `engine/stockfish.exe` в git не попадает.

`on_update` вызывается из фонового потока; `window.evaluate_js` в pywebview
можно вызывать из любого потока.

## Компоненты

### `backend/game.py` — `GameSession`

Единственный источник правды о партии. Не знает ни про движок, ни про окно.

- `new_game(my_color: "white" | "black")` — начальная позиция, запоминает цвет пользователя.
- `move(from_sq: str, to_sq: str) -> bool` — делает ход, если он законный.
  Если пешка доходит до последней горизонтали, превращение всегда в ферзя.
  Незаконный ход → `False`, позиция не меняется.
  После конца партии (мат, пат, ничья, наступающая сама) ход отклоняется с ошибкой «Партия окончена — начни новую или отмени ход».
- `undo() -> bool` — отменяет один полуход; `False`, если отменять нечего.
- `load_fen(fen: str) -> bool` — ставит позицию из FEN (на случай, если партия уже идёт); цвет пользователя не меняется, история очищается. Нужны минимум три поля (расстановка, чей ход, рокировки), иначе ошибка «Неполный FEN…». Невалидная позиция → `False`, позиция не меняется, в ошибке названа причина (например, «нет белого короля»).
- `state() -> dict` — снимок состояния для фронта (формат ниже).
- `is_my_turn() -> bool` — ход за пользователем и партия не окончилась сама (`board.outcome()` без `claim_draw` равен `None`).

### `backend/engine.py` — `EngineAnalyzer`

Обёртка над Stockfish через `chess.engine.SimpleEngine.popen_uci`.

- Настройки движка: `MultiPV = 3`, `Threads = 2`, `Hash = 128`.
- `analyze(fen: str, pov: chess.Color, on_update)` — запускает анализ в фоновом
  потоке. Предыдущий анализ, если идёт, останавливается. Анализ заканчивается при
  глубине 20 или через 4 секунды — что раньше.
- `on_update(result)` вызывается при каждом росте глубины, начиная с глубины 8,
  но не чаще раза в 250 мс; последний результат отправляется всегда.
- `stop()` — останавливает текущий анализ (вызывается на ходу соперника, при отмене, новой игре).
- `close()` — завершает процесс движка при закрытии окна.
- Результаты в окно доставляет отдельный поток-курьер: воркер кладёт результат
  в «почтовый ящик» на одно место (новый вытесняет недоставленный старый), курьер
  вызывает on_update. Воркер движка никогда не ждёт окно.
- `stop()` ждёт завершения воркера и текущей доставки не дольше STOP_TIMEOUT (2 с);
  `close()` ждёт замок не дольше CLOSE_TIMEOUT (5 с) и закрывает движок в любом
  случае; повторный `close()` возвращается сразу.
- Ошибка `configure` после запуска процесса закрывает процесс.
- О падении движка сообщается сразу через колбэк `on_error` (в окне —
  `window.onEngineError`).
- Ошибки доставки и падения пишутся в лог (`logging`).
- Если `stockfish.exe` не найден → `EngineAnalyzer` создаётся в состоянии ошибки,
  `analyze()` ничего не делает, текст ошибки доступен в `error`.
- Если процесс движка упал во время анализа → сообщение в панели сразу; при следующем `analyze()` движок перезапускается один раз. Если он упадёт снова до первого успешного анализа — подсказки отключены до перезапуска приложения. Успешный анализ снова разрешает один перезапуск.

Оценка всегда считается **с точки зрения пользователя** (`pov` = его цвет):
плюс — хорошо для пользователя.

### `backend/api.py` — `Api`

Класс, который передаётся в pywebview как `js_api`. Держит `GameSession` и
`EngineAnalyzer`, после каждого изменения позиции решает, запускать ли анализ:
если `is_my_turn()` — `analyze(...)`, иначе — `stop()`.

Каждое изменение позиции (новая партия, ход, отмена, FEN) увеличивает номер версии
`rev`. Он есть в каждом `state` и в каждом результате анализа, поэтому фронт
отбрасывает запоздавшие ответы и не теряет анализ, пришедший раньше ответа на ход.
Ошибка действия (`state.error`) возвращается только в ответе этого действия:
`get_state()` и `set_on_top()` отдают `error: null`.

Методы (все возвращают `state`):

| Метод | Действие |
|---|---|
| `get_state()` | текущее состояние |
| `new_game(my_color)` | новая партия |
| `move(from_sq, to_sq)` | ход; при незаконном ходе в `state.error` текст ошибки |
| `undo()` | отмена полухода |
| `load_fen(fen)` | позиция из FEN |
| `set_on_top(flag)` | окно поверх всех / обычное |

Результаты анализа бэк сам отправляет во фронт:
`window.evaluate_js("window.onAnalysis(<json>)")`.

### `frontend/main.js`

- Доска `chessground`: ориентация по `my_color`, разрешённые ходы берутся из
  `state.dests`, после хода вызывается `pywebview.api.move(from, to)` и доска
  перерисовывается по возвращённому `state.fen` (незаконный ход визуально
  откатывается сам).
- Стрелки — `autoShapes` chessground: 1-й ход кисть `green`, 2-й `blue`, 3-й `yellow`.
- Панель справа: чей ход, статус (шах / мат / пат / ничья), список топ-3
  (`Nf3  +2.3`, `Qh5  мат в 3`), глубина расчёта, две кнопки **Новая за белых** /
  **Новая за чёрных**, **Отменить** (+ Ctrl+Z), **Поверх всех окон** (переключатель),
  поле для FEN с кнопкой **Загрузить**.
- При запуске приложения сразу открыта новая партия за белых.
- `window.onAnalysis(result)` сравнивает result.rev с текущим state.rev: старый отбрасывает, более новый откладывает до прихода его состояния, совпадающий рисует (только на ходу пользователя). Ответ API со старым rev тоже не рисуется.
- window.onEngineError(message) показывает сообщение о падении движка и стирает подсказки.
- «Новая за белых/чёрных» при непустой партии требует второго нажатия в течение 3 с.
- Enter в поле FEN загружает позицию; Ctrl+Z без Shift/Alt, автоповтор зажатой клавиши игнорируется.
- Статус: «Игра окончена: Ничья (причина)» для ничьей, наступающей самой;
  «… · можно потребовать ничью: троекратное повторение / 50 ходов…» без остановки подсказок.
- История нумеруется от history_start: после FEN с ходом чёрных — «1... e5 2. Nf3».
- На ходу соперника стрелки и список очищаются.

## Форматы данных

`state`:

```json
{
  "fen": "…",
  "turn": "white",
  "my_color": "white",
  "dests": {"e2": ["e3", "e4"]},
  "last_move": ["e7", "e5"],
  "status": "playing",
  "draw_reason": null,
  "claimable_draw": null,
  "history": ["e4", "e5"],
  "history_start": {"number": 1, "turn": "white"},
  "error": null,
  "rev": 7,
  "engine_error": null
}
```

- `status`: `"playing" | "check" | "checkmate" | "stalemate" | "draw"`; `"draw"` — только
  ничья, наступающая сама: нехватка материала, пятикратное повторение, 75 ходов.
- `draw_reason`: `null | "insufficient_material" | "fivefold_repetition" | "seventyfive_moves"`.
- `claimable_draw`: `null | "threefold_repetition" | "fifty_moves"` — партия продолжается,
  подсказки работают.
- `dests` пуст, когда партия окончена.
- `history_start`: номер хода и цвет первого полухода истории (корень — начальная позиция или FEN).
- `last_move`: `null` в начальной позиции.
- `error`: текст ошибки действия (незаконный ход, плохой FEN, партия окончена) или `null`.
- `rev`: номер версии позиции.

Результат анализа (`onAnalysis`):

```json
{
  "fen": "...",
  "depth": 18,
  "rev": 7,
  "lines": [
    {"uci": "g1f3", "san": "Nf3", "score": {"cp": 230, "mate": null}},
    {"uci": "e2e4", "san": "e4",  "score": {"cp": 190, "mate": null}},
    {"uci": "d2d4", "san": "d4",  "score": {"cp": 170, "mate": null}}
  ]
}
```

- `score.cp` — сантипешки с точки зрения пользователя; `score.mate` — число ходов
  до мата (плюс — пользователь ставит мат, минус — ему ставят); одно из полей `null`.
- `lines` может содержать меньше трёх ходов, если законных ходов меньше.

## Поток данных

1. Пользователь двигает фигуру → `main.js` → `api.move(from, to)`.
2. `GameSession.move` проверяет ход; `Api` решает: мой ход → `analyze`, иначе `stop`.
3. `move` возвращает `state` → фронт перерисовывает доску и панель.
4. Фоновый поток движка шлёт `onAnalysis` по мере роста глубины → фронт рисует
   стрелки и список.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет `stockfish.exe` | доска работает, в панели сообщение с путём, куда положить движок |
| Движок упал | сообщение в панели сразу; один перезапуск на следующем ходе; повторное падение до успешного анализа — подсказки отключены до перезапуска приложения |
| Незаконный ход | фигура возвращается, позиция не меняется |
| Невалидный или неполный FEN | позиция не меняется, под полем ввода причина |
| Промах при вводе хода | кнопка «Отменить» / Ctrl+Z |
| Партия окончена сама (мат, пат, нехватка материала, 5-кратное повторение, 75 ходов) | ходы не принимаются, статус с причиной |
| Зависло окно (evaluate_js) | stop()/close() не ждут дольше таймаутов, движок закрывается |

## Тестирование

`tests/test_game.py` (без движка):
- законный ход меняет FEN, незаконный — нет;
- автопревращение в ферзя;
- `undo` откатывает полуход, на пустой истории возвращает `False`;
- `dests` в нужном формате (клетка → список клеток);
- статусы: шах, мат (детский мат), пат;
- `load_fen`: валидный ставит позицию, невалидный не меняет;
- `is_my_turn` для белых и чёрных;
- рокировка, взятие на проходе, превращение чёрных со взятием;
- троекратное повторение и 50 ходов — «можно потребовать ничью», 75 ходов и нехватка материала — конец партии;
- неполный FEN и причина невалидного FEN; history_start после FEN с ходом чёрных.

`tests/test_engine.py` (с настоящим Stockfish; пропускается, если файла нет):
- в позиции с матом в 1 первый вариант — этот мат, `score.mate == 1`;
- в начальной позиции приходит 3 варианта;
- оценка с точки зрения чёрных имеет правильный знак;
- `stop()` прекращает обновления.

`tests/test_engine_unit.py` (без Stockfish, процесс подменён фейком):
- `build_result`: знак оценки с точки зрения пользователя, пропуск info без pv/score, меньше трёх линий;
- ошибка `configure` закрывает процесс;
- падение → сообщение → один перезапуск; повторное падение — без перезапуска; успешный анализ снова разрешает перезапуск;
- повторный `close()` мгновенный; зависшая доставка не вешает `stop()`/`close()`.

`tests/test_api.py` (с фейковым движком):
- анализ на своём ходу и остановка на чужом, отмена, FEN;
- `rev` растёт только при смене позиции и приходит в результатах анализа;
- ошибка действия не повторяется в `get_state()`/`set_on_top()`;
- набор публичных методов и параллельные вызовы из нескольких потоков.

Интерфейс проверяется запуском `app.py` вручную: ход мышкой, стрелки на своём
ходу, их отсутствие на чужом, отмена, разворот доски для чёрных, «поверх всех окон».

## Настройка (кратко, подробно — в README)

```
uv sync                   # .venv и зависимости из uv.lock
# stockfish.exe → engine/
uv run app.py
uv run pytest -q
```

chessground уже скопирован в frontend/vendor/; npm нужен только для обновления его версии.
