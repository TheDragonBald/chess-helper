# Архитектура «Шахматного помогатора»

Документ описывает, как помогатор устроен внутри: из каких частей состоит, какие библиотеки использует, как идут данные и потоки и почему сделано именно так. Что это за проект и как им пользоваться — в [ABOUT_PROJECT.md](ABOUT_PROJECT.md), установка и запуск — в [README](../README.md).

## Коротко

Это десктоп-окно на Windows. Бэкенд на Python хранит партию и общается со Stockfish, фронтенд на чистом JavaScript рисует доску и панель. Оба живут в одном окне pywebview (Edge WebView2): JS вызывает методы Python через мост `window.pywebview.api`, а Python отправляет подсказки в JS через `window.evaluate_js`.

```
┌──────────────────────────── окно pywebview (WinForms + Edge WebView2) ───────────────────────────┐
│  frontend/ (JS)                                                                                   │
│   index.html ─ main.js ─ chessground (доска)                                                      │
│      │  window.pywebview.api.move(...) и др.            ▲  window.onAnalysis(...)                 │
│      ▼                                                  │  window.onEngineError(...)              │
└──────┼──────────────────────────────────────────────────┼─────────────────────────────────────────┘
       │ поток js_api (на каждый вызов свой)               │ evaluate_js
       ▼                                                  │
  backend/api.py — Api ─────────────► backend/engine.py — EngineAnalyzer ──► курьер ──┘
       │  (Api._lock, номер версии rev)    │  воркер анализа
       ▼                                   ▼
  backend/game.py — GameSession       python-chess (UCI) ──► engine/stockfish.exe (отдельный процесс)
  (правила, статусы, FEN, история)
```

## Компоненты

### `app.py` — сборка приложения

- Первым делом `setup_logging()`: `WARNING` и выше — в `%LOCALAPPDATA%\chess-helper\logs\helper.log` (до трёх файлов по 1 МБ) и в консоль, если она есть; необработанные исключения, в том числе в потоках, тоже пишутся в лог.
- С аргументами `--self-check <отчёт>` запускает самопроверку собранного exe и выходит с её кодом.
- Иначе `check_startup()`: без WebView2 или если .NET-часть окна не загрузилась — системное окно с объяснением, и помогатор закрывается. Тяжёлые модули (pywebview, бэкенд) импортируются только после этого, в `run_app()`.
- Создаёт `GameSession`, `EngineAnalyzer(on_error=…)` и `Api`, затем окно `webview.create_window("Шахматный помогатор", "frontend/index.html", js_api=api, width=900, height=640, min_size=(760, 600))`.
- Даёт бэкенду три колбэка: `push_analysis` → `window.onAnalysis(<json>)`, `push_engine_error` → `window.onEngineError(<json>)` (оба через `window.evaluate_js`) и `set_on_top` → `apply_on_top`.
- `webview.start(http_server=True, icon=…/assets/icon.ico)` раздаёт `frontend/` встроенным сервером; `icon` нужен для иконки окна при запуске из исходников (в exe pywebview берёт её из файла exe). Движок закрывается дважды: в обработчике `window.events.closed` и в `finally` (на случай, если `start()` упал). Второй вызов ничего не ждёт.
- `apply_on_top(window, flag)` — обход бага pywebview 6.2.1: там `TopMost` ставится прямо из потока js_api, который держит GIL и ждёт UI-поток, а UI-потоку для ответа нужен тот же GIL — окно зависало намертво. Мы выставляем `TopMost` в UI-потоке через `Form.Invoke`, как это уже сделано в основной ветке pywebview. Не на Windows — штатный `window.on_top`. Обход можно убрать, когда выйдет pywebview новее 6.2.1.

### `backend/game.py` — `GameSession`

Единственный источник правды о партии; не знает ни про движок, ни про окно.

- `new_game(my_color)` — начальная позиция и цвет пользователя (`"white"`/`"black"`, иначе `ValueError`).
- `move(from_sq, to_sq)` — законный ход или ошибка («Неверная клетка…», «Незаконный ход…»). Пешка на последней горизонтали всегда превращается в ферзя. После конца партии ход отклоняется: «Партия окончена — начни новую или отмени ход».
- `undo()` — отмена полухода.
- `load_fen(fen)` — позиция из FEN, история обнуляется, цвет пользователя не меняется. Нужны минимум три поля (расстановка, чей ход, рокировки), иначе «Неполный FEN…» — иначе python-chess молча подставил бы «ход белых, без рокировок». Невалидная позиция объясняется по флагам `board.status()`: «нет белого короля», «права на рокировку не сходятся…» и т. д.
- `status()` / `state()` строятся по `board.outcome()` **без** `claim_draw`:
  - `checkmate`, `stalemate`, `draw` — только окончания, наступающие сами (нехватка материала, пятикратное повторение, 75 ходов); причина ничьей — в `draw_reason`, `dests` пуст, ходы не принимаются;
  - троекратное повторение и 50 ходов — не конец партии, а `claimable_draw` («можно потребовать ничью»): подсказки продолжают работать, потому что в Discord партия может идти дальше;
  - `check` / `playing` — партия идёт.
- `is_my_turn()` — ход пользователя и партия не окончена; от этого зависит, запускать ли анализ.
- `history()` — SAN всех ходов от корня (позиции старта или загруженного FEN); `history_start` — номер и цвет первого полухода, чтобы фронт показал «12... e5».

### `backend/engine.py` — `EngineAnalyzer`

Обёртка над `chess.engine.SimpleEngine`, у которой ни один вызов из окна не может зависнуть.

**Настройки** (константы модуля):

| Константа | Значение | Смысл |
|---|---|---|
| `DEFAULT_PATH` | `engine/stockfish.exe` | Путь к движку; переопределяется переменной `STOCKFISH_PATH` |
| `ENGINE_OPTIONS` | `{"Threads": 2, "Hash": 128}` | UCI-опции Stockfish |
| `MULTIPV` | 3 | Сколько лучших ходов считать |
| `MAX_DEPTH` / `MAX_TIME` | 20 / 4.0 с | Анализ заканчивается при глубине 20 или через 4 с — что раньше |
| `MIN_DEPTH_TO_SEND` | 8 | Промежуточные результаты — начиная с этой глубины |
| `SEND_INTERVAL` | 0.25 с | Промежуточные результаты — не чаще этого |
| `STOP_TIMEOUT` | 2.0 с | Сколько `stop()` ждёт воркер и текущую доставку |
| `CLOSE_TIMEOUT` | 5.0 с | Сколько `close()` ждёт замок, прежде чем закрыть движок без него |

**Публичные методы:**

- `analyze(position, pov, on_update)` — останавливает прошлый анализ и запускает новый в фоновом потоке. `position` — копия доски партии **вместе с историей ходов** (так Stockfish видит повторения и не советует в выигрыше ход, дающий троекратное повторение); FEN-строка тоже принимается. Оценка всегда с точки зрения `pov` — цвета пользователя.
- `stop()` — останавливает текущий анализ; ждёт не дольше `STOP_TIMEOUT`.
- `close()` — завершает процесс движка; идемпотентен.
- `wait(timeout)` — ждёт конца анализа и доставки последнего результата (нужен тестам).
- `error` — текст ошибки движка или `None`; `Api` кладёт его в `state.engine_error`.

**Как идёт анализ:**

1. `analyze()` увеличивает номер анализа `_token` и запускает поток-воркер.
2. Воркер итерирует `engine.analysis(board, Limit(depth=20, time=4), multipv=3)`. Промежуточный результат отправляется, когда пришли все линии текущей глубины, глубина ≥ 8 и прошло ≥ 0.25 с; финальный — всегда.
3. Результат (`build_result`: ход в UCI и SAN, оценка `cp`/`mate` с точки зрения пользователя, глубина) воркер кладёт в «почтовый ящик» на одно место — новое сообщение вытесняет недоставленное старое.
4. Отдельный поток-курьер забирает сообщение, отбрасывает устаревшее (номер анализа сменился) и вызывает `on_update` — то есть `window.evaluate_js`. Если окно зависнет, зависнет только курьер: воркер, `stop()` и `close()` его не ждут дольше таймаутов.

**Падения:**

- Ошибка `configure` после запуска процесса — процесс закрывается (иначе фоновый поток python-chess не дал бы приложению завершиться).
- Процесс упал во время анализа (`EngineError`/`TimeoutError`) — движок закрывается, сообщение сразу уходит в окно через `on_error` («Stockfish упал: <причина>. Перезапущу его, когда снова будет твой ход»). Настоящая причина берётся из `__context__`: python-chess перекрывает её ошибкой «event loop dead» из `__exit__`.
- Перезапуск — один, при следующем `analyze()`. Если движок снова упадёт до первого анализа, давшего результат, подсказки отключаются до перезапуска помогатора («Stockfish снова упал…»). Успешный анализ снова разрешает один перезапуск.
- Ошибка в нашем коде разбора (не в Stockfish) не считается падением: движок не трогаем, в окно — «Ошибка анализа: …», в лог — traceback.

### `backend/api.py` — `Api`

Объект, который pywebview отдаёт в JS как `window.pywebview.api`. Публичных методов ровно шесть (это проверяет тест): `get_state`, `new_game`, `move`, `undo`, `load_fen`, `set_on_top`. Все возвращают `state`.

- pywebview вызывает каждый метод в **отдельном потоке**, а `GameSession` не потокобезопасна, поэтому тело каждого метода — под `Api._lock`.
- Каждое изменение позиции (новая партия, удачный ход, отмена, FEN) увеличивает номер версии `rev`. Если теперь ход пользователя — `engine.analyze(board.copy(), my_color, …)` с колбэком, который добавляет к результату `rev` этой позиции; иначе — `engine.stop()`.
- Ошибка действия (`state.error`) возвращается только в ответе этого действия; `get_state()` и `set_on_top()` отдают `error: null`, чтобы старая ошибка не «залипала».

### `frontend/` — окно

- `index.html` — разметка панели (статус, список ходов `#lines`, глубина, ошибки движка и действия, кнопки «Новая за белых» / «Новая за чёрных» / «Отменить», галочка «Поверх всех окон», поле FEN и «Загрузить», история) и import map: `chessground` → `./vendor/chessground/dist/chessground.js`.
- `main.js`:
  - доска `Chessground` с ориентацией по цвету пользователя, разрешёнными ходами из `state.dests`, без премувов; после хода — `api.move(from, to)`;
  - `call(fn)` — общий вызов бэка: рисует ответ, при исключении показывает ошибку и пересинхронизируется через `get_state()`;
  - `render(state)` — не рисует ответ со `rev` меньше текущего (ответы потоков могут прийти не по порядку); при смене `rev` стирает стрелки;
  - `window.onAnalysis(result)` — результат старой позиции отбрасывает, более новой — откладывает в `pendingAnalysis` до прихода её состояния (так подсказка «мат в 1», посчитанная за 10 мс, не теряется), совпадающий — рисует, только на ходу пользователя;
  - стрелки — `autoShapes` кистями `green`/`blue`/`yellow` (зелёная рисуется последней, поверх); список — `SAN  оценка` («+0.3», «мат в 2», «тебе мат в 3»; около нуля — «0.0»);
  - `window.onEngineError(message)` — сообщение о падении движка и очистка подсказок;
  - статус: «Твой ход» / «Ход соперника — повтори его», «Шах!», «можно потребовать ничью: …», «Игра окончена: Мат / Пат / Ничья (причина)»;
  - история с номерами от `history_start`;
  - «Новая за…» при непустой партии требует второго нажатия в течение 3 с; второе нажатие быстрее 0.4 с считается двойным кликом и игнорируется;
  - Ctrl+Z (по `e.code`, работает на любой раскладке) — отмена, без Shift/Alt и без автоповтора; в текстовом поле не перехватывается; Enter в поле FEN — загрузка;
  - на старте — `new_game('white')` после события `pywebviewready`.

## Потоки данных

### Ход пользователя

1. Пользователь двигает фигуру → chessground вызывает `onUserMove(orig, dest)` → `api.move(orig, dest)`.
2. Поток js_api: `Api.move` → `GameSession.move` → `rev += 1` → ход пользователя? `analyze(...)` : `stop()` → возвращает `state`.
3. JS: `render(state)` — доска, статус, история; стрелки стёрты, потому что `rev` сменился.
4. Воркер считает → курьер → `window.onAnalysis({..., rev})` → стрелки и список (или ожидание в `pendingAnalysis`, если ответ на ход ещё в пути).

### Падение Stockfish

Воркер ловит `EngineError` → движок закрыт, `engine.error` выставлен → курьер → `window.onEngineError(...)` → в панели сообщение. При следующем ходе пользователя `analyze()` перезапускает движок один раз; удачный перезапуск очищает `engine_error` в следующем `state`.

### Закрытие окна

pywebview запускает обработчик `closed` в отдельном потоке → `engine.close()`: остановить анализ, подождать не дольше `STOP_TIMEOUT`, `quit()` процессу (при ошибке — `close()`), разбудить курьера, чтобы он вышел. Затем `finally` в `app.py` вызывает `close()` ещё раз — он возвращается сразу. Процесс Python завершается сам.

## Потоки и синхронизация

| Поток | Кто создаёт | Что делает |
|---|---|---|
| UI-поток (главный) | `webview.start()` | Окно WinForms и WebView2, события окна |
| Поток js_api | pywebview, по одному на каждый вызов из JS | Методы `Api` под `Api._lock` |
| Воркер анализа | `EngineAnalyzer.analyze()`, daemon | Итерация анализа python-chess, кладёт результаты в ящик |
| Курьер | `EngineAnalyzer.__init__()`, daemon | Достаёт сообщения из ящика, вызывает `on_update`/`on_error` → `evaluate_js` |
| Цикл событий python-chess | `SimpleEngine.popen_uci()`, не daemon | Общение с процессом Stockfish по UCI |
| Обработчик `closed` | pywebview | `engine.close()` |

Замки: `Api._lock` (вызовы из JS) → `EngineAnalyzer._api_lock` (RLock: `analyze`/`stop`/`close`) → `_lock` (состояние анализа) или `_mail` (Condition почтового ящика). `_lock` и `_mail` не вкладываются друг в друга; воркер и курьер не берут `_api_lock`; курьер вызывает окно вне всех замков. Поэтому взаимных блокировок между нашими потоками нет, а зависшее окно не блокирует движок.

## Форматы данных

`state` — ответ каждого метода `Api`:

```json
{
  "fen": "rnbqkbnr/pppp1ppp/8/4p3/4P3/8/PPPP1PPP/RNBQKBNR w KQkq - 0 2",
  "turn": "white",
  "my_color": "white",
  "dests": {"g1": ["f3", "h3"], "e1": ["e2"]},
  "last_move": ["e7", "e5"],
  "status": "playing",
  "draw_reason": null,
  "claimable_draw": null,
  "history": ["e4", "e5"],
  "history_start": {"number": 1, "turn": "white"},
  "error": null,
  "rev": 3,
  "engine_error": null
}
```

- `status`: `playing | check | checkmate | stalemate | draw`.
- `draw_reason`: `null | insufficient_material | fivefold_repetition | seventyfive_moves`.
- `claimable_draw`: `null | threefold_repetition | fifty_moves`.

Результат анализа — аргумент `window.onAnalysis`:

```json
{
  "fen": "…",
  "depth": 18,
  "rev": 3,
  "lines": [
    {"uci": "g1f3", "san": "Nf3", "score": {"cp": 31, "mate": null}},
    {"uci": "b1c3", "san": "Nc3", "score": {"cp": 24, "mate": null}},
    {"uci": "f1c4", "san": "Bc4", "score": {"cp": 18, "mate": null}}
  ]
}
```

`score.cp` — сантипешки с точки зрения пользователя; `score.mate` — ходов до мата (плюс — мат ставит пользователь, минус — ему). Линий может быть меньше трёх, если законных ходов меньше.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет `stockfish.exe` | Доска работает, в панели — путь, куда положить движок |
| Движок не принял настройки | Процесс закрыт, в панели «Не удалось запустить Stockfish…» |
| Движок упал | Сообщение сразу; один перезапуск на следующем ходе пользователя; повторное падение до успешного анализа — подсказки выключены до перезапуска |
| Ошибка разбора анализа | «Ошибка анализа: …» в панели, traceback в лог, движок работает |
| Незаконный ход | Фигура возвращается, позиция не меняется, текст ошибки под полем FEN |
| Неполный или невалидный FEN | Позиция не меняется, причина под полем |
| Партия окончена сама | Ходы не принимаются, статус с причиной; отмена работает |
| Окно зависло на `evaluate_js` | `stop()`/`close()` не ждут дольше таймаутов, движок закрывается |
| Исключение при вызове бэка из JS | Ошибка показывается, доска пересинхронизируется через `get_state()` |
| Нет WebView2 | До окна — системное сообщение со ссылкой на страницу загрузки Microsoft |
| .NET-часть окна не загрузилась (например, файлы заблокированы как скачанные из интернета) | Системное сообщение с инструкцией «Свойства → Разблокировать», трассировка в лог |
| Необработанное исключение | Пишется в лог с трассировкой |

## Сборка exe

Релиз — zip с папкой `chess-helper/`: `chess-helper.exe` без консоли, `chess-helper.exe.config`, служебная папка `_internal/` (Python, библиотеки, `frontend/`, `assets/icon.ico`, `engine/stockfish.exe`), `LICENSE`, `README.txt` и `licenses/`.

- **Скрипт** `uv run --group build python scripts/build_exe.py`: версия из `pyproject.toml` (с `--expect-tag` — сверка с тегом); Stockfish sf_19 в кэш `build/cache/stockfish-sf_19/` со сверкой SHA-256; PyInstaller по `chess-helper.spec`; движок, `chess-helper.exe.config`, `LICENSE`, `README.txt` из `packaging/` и лицензии всех пакетов сборки (обход зависимостей по метаданным; если файла нет — текст из `packaging/licenses/`, иначе ошибка); самопроверка; самопроверка на копии с меткой «из интернета»; zip `dist/chess-helper-v<версия>-windows-x64.zip`. С `--stockfish-only` только готовит движок.
- **Что не попадает в сборку.** В `chess-helper.spec` стоит `excludes=["setuptools", "_decimal"]`. Пакет setuptools во время работы не нужен (cffi импортирует его только при компиляции), а тянет в сборку `packaging` и вшитые библиотеки без лицензий. Без `_decimal` модуль `decimal` переходит на чистый Python (`_pydecimal`), и библиотека mpdecimal в сборку не попадает.
- **Лицензии.** Кроме лицензий пакетов из метаданных, в `packaging/licenses/` лежат тексты для proxy-tools (в пакете нет файла лицензии) и для библиотек, встроенных в pywebview (WebView2 SDK) и в сборку Python (OpenSSL, libffi, expat). Скрипт сборки кладёт их в `licenses/` вместе с лицензиями Python, Stockfish и chessground.
- **Пути в exe.** `backend/paths.app_root()` — `sys._MEIPASS` (папка `_internal`) в сборке и корень репозитория в исходниках; фронтенд pywebview находит сам.
- **Без чёрного окна.** Stockfish запускается с `CREATE_NO_WINDOW`: иначе у exe без консоли Windows открыла бы для движка отдельное окно консоли.
- **Лог.** `backend/logs.py` — файл в `%LOCALAPPDATA%\chess-helper\logs\`, перехват `sys.excepthook` и `threading.excepthook`.
- **Проверка при старте.** `backend/startup_check.py` импортирует `webview.platforms.winforms` и читает его `renderer`: решение принимает сам pywebview, поэтому проверка с ним не расходится. Без WebView2 pywebview выбрал бы Internet Explorer, в котором доска не работает.
- **Метка «из интернета».** Проводник помечает файлы из скачанного zip, а .NET Framework не грузит такие DLL через `Assembly.LoadFrom` без `loadFromRemoteSources` — её включает `chess-helper.exe.config`. Скрипт сборки проверяет это самопроверкой на помеченной копии.
- **Самопроверка.** `chess-helper.exe --self-check <отчёт>`: файлы сборки, вложенный Stockfish (без учёта `STOCKFISH_PATH`) считает начальную позицию, грузится .NET-часть окна (`webview.platforms.edgechromium`); строки `OK`/`FAIL`/`INFO`, код 0 или 1.
- **Иконка.** `assets/icon.svg` — исходник; `scripts/make_icon.py` рендерит его headless Edge в PNG 512×512 и собирает `assets/icon.ico` Pillow'ом. `msedge.exe` может перезапустить себя и выйти, когда картинки ещё нет, поэтому скрипт ждёт, пока появится PNG и Edge отпустит временный профиль (исчезнет `lockfile`). В exe иконку окна pywebview берёт из файла exe.
- **GitHub Actions** (`.github/workflows/release.yml`): по тегу `v*` на `windows-latest` — Stockfish, тесты с настоящим движком, сборка, черновик релиза; ручной запуск — то же без релиза.

## Решения и почему

- **pywebview, а не Electron/Qt.** Бэкенд на Python с python-chess, интерфейс на обычном JS с готовой доской chessground, одно лёгкое окно на системном WebView2.
- **Ввод вручную, без чтения экрана.** Надёжно и просто: пользователь повторяет ходы из Discord на доске помогатора.
- **Курьер доставки.** `evaluate_js` в pywebview синхронный и без таймаута; если окно зависнет, оно не должно утащить за собой движок и закрытие приложения.
- **Номер версии `rev`.** Каждый вызов из JS идёт в своём потоке, и ответы с подсказками приходят в произвольном порядке; `rev` однозначно говорит, к какой позиции относится ответ.
- **`outcome()` без `claim_draw`.** Возможность потребовать ничью — не конец партии: в Discord игра может продолжиться, и подсказки нужны.
- **Доска с историей в движок.** Без истории Stockfish не видит повторений позиции.
- **chessground в репозитории.** Для запуска не нужен npm; лицензия GPL-3.0, поэтому и весь проект под GPL-3.0.
- **Сборка папкой, а не одним exe.** Один exe при каждом запуске распаковывается во временную папку вместе с движком на десятки мегабайт, стартует медленнее и чаще смущает антивирусы.
- **Проверка WebView2 через сам pywebview.** Своя копия его логики могла бы с ним разойтись; спрашивать `renderer` у pywebview надёжнее.

## Известные ограничения

- Только Windows: pywebview на WinForms + WebView2, сборка Stockfish под Windows.
- Превращение пешки — всегда в ферзя; иную фигуру можно поставить через FEN ([#16](https://github.com/TheDragonBald/chess-helper/issues/16)).
- Интерфейс на русском ([#15](https://github.com/TheDragonBald/chess-helper/issues/15)).
- Обход `apply_on_top` нужен до выхода pywebview новее 6.2.1 ([#11](https://github.com/TheDragonBald/chess-helper/issues/11)).
- Нет сторожа зависаний и дампа потоков ([#12](https://github.com/TheDragonBald/chess-helper/issues/12)).
- Exe без цифровой подписи: при первом запуске SmartScreen предупреждает.
- Открытые доработки и идеи — в issues; список по темам — в разделе [«Планы»](ABOUT_PROJECT.md#планы) файла ABOUT_PROJECT.
